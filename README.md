# Token Drift Detector

A VS Code extension that keeps your design system honest — detecting hard-coded colors, spacing, and typography values that should be design tokens, right as you type.

---

## What it does

When a developer writes `color: #2563eb` instead of `color: var(--color-brand-primary)`, Token Drift Detector catches it immediately with a yellow underline, explains which token matches, and offers a one-click fix.

**Core loop:**

1. You define your tokens in `tokens.dtcg.json` (DTCG format)
2. The extension scans every CSS/TS/JS/Vue/Astro file you edit
3. Hard-coded values that match tokens get flagged
4. A quick-fix lightbulb replaces the value or records the intentional exception
5. The CI workflow blocks pull requests that introduce new violations
6. The team dashboard shows compliance trends over time

---

## Features

### In-editor detection

- Yellow (`Warning`) underlines on values that match a design token
- Blue (`Information`) underlines on unrecognized values with no token match — with a flow to propose the value as a new token
- Hover tooltip shows the matched token name and the `var(--…)` reference to use

### Code actions (lightbulb / Cmd+.)

| Action | What it does |
|---|---|
| **Use Token** | Replaces the hard-coded value with `var(--token-name)` |
| **Mark as Intentional** | Prompts for a reason, writes an entry to `token-exceptions.json`, suppresses future warnings |
| **Suggest as New Token** | Prompts for a name (e.g. `color.brand.orange`), appends the token to `tokens.dtcg.json`, auto-reloads the index |

### CI gate (GitHub Actions)

The included workflow scans every changed file on push and pull request:

- Posts a markdown table to the PR listing every violation with file, line, value, and type
- Fails the build if violations are found
- Set the repo variable `ALLOW_NEW_COLORS=true` to warn instead of fail (useful during migration)
- Respects `// token-skip-line` comments for intentional bypasses

### Team dashboard

A zero-dependency HTML dashboard shows:

- **Live metrics** — files scanned, violations found, compliance rate, pending approvals
- **Trend chart** — weekly compliance rate with animated SVG bezier curve
- **Exception log** — every intentional exception with colour swatch, age badge, and reason
- **Pending approvals** — proposed new tokens waiting for a maintainer to merge

Deploy it automatically to GitHub Pages on every push to `main`.

## Setup

### 1. Add your tokens file

Place `tokens.dtcg.json` at the **root of your workspace** (same folder you open in VS Code).

```json
{
  "$schema": "https://tr.designtokens.org/format/",
  "color": {
    "$type": "color",
    "brand": {
      "primary": { "$value": "#2563eb", "$type": "color" },
      "secondary": { "$value": "#7c3aed", "$type": "color" }
    },
    "feedback": {
      "error": { "$value": "#dc2626", "$type": "color" }
    }
  },
  "spacing": {
    "$type": "dimension",
    "sm":  { "$value": "8px",  "$type": "dimension" },
    "md":  { "$value": "16px", "$type": "dimension" },
    "lg":  { "$value": "24px", "$type": "dimension" }
  }
}
```

The extension parses any depth of nesting. Token names are derived from the key path: `color.brand.primary` → `var(--color-brand-primary)`.

### 2. Open any CSS/TS/JS file

The extension activates automatically when you open a file in a supported language. The status bar shows the number of loaded tokens (e.g. **⟳ 14 tokens**). Click it to reload after editing `tokens.dtcg.json`.

### 3. (Optional) Add the CI workflow

Copy `.github/workflows/token-check.yml` into your own repository. No additional secrets are required — it uses the built-in `GITHUB_TOKEN`.

### 4. (Optional) Enable the dashboard

The dashboard reads three JSON files relative to itself:

| File | Purpose |
|---|---|
| `dashboard-data.json` | Generated by `scripts/generate-dashboard-data.sh` on each CI run |
| `token-exceptions.json` | Written by the extension when developers mark intentional exceptions |
| `pending-tokens.json` | Populated when developers suggest new tokens |

To preview locally:

```bash
# From the project root
python -m http.server 8080
# Open http://localhost:8080/dashboard/
```

The CI workflow deploys the dashboard to GitHub Pages on every push to `main`.

## How scanning works

The scanner checks every line of changed files against two lists extracted from `tokens.dtcg.json`:

- **Color values** — hex strings like `#2563eb`
- **Dimension values** — pixel strings like `16px`

A line is **skipped** if it:

- Starts with `//`, `/*`, or `*` (comments)
- Contains `var(--)` (already using a token reference)
- Contains `url(` (background images)
- Is inside a string literal
- Has a `// token-skip-line` inline comment

Everything else is flagged.

---

## Skipping lines intentionally

Add `// token-skip-line` to any line to suppress detection for that line only:

```css
.logo {
  background: #2563eb; /* token-skip-line */
}
```

Or use the **Mark as Intentional** code action — it writes to `token-exceptions.json` so the exception is tracked and visible in the dashboard.

## Commands

| Command | Description |
|---|---|
| `Token Drift: Reload tokens.dtcg.json` | Re-parses the token file and updates the status bar count |
| `Token Drift: Use Token` | Replaces the flagged value with the matching `var(--…)` reference |
| `Token Drift: Mark as Intentional` | Records the exception to `token-exceptions.json` with an optional reason |
| `Token Drift: Suggest as New Token` | Appends the value as a new token to `tokens.dtcg.json` |

## Token format

Tokens must follow the [W3C Design Tokens Community Group](https://tr.designtokens.org/format/) (DTCG) spec:

- Leaf tokens have `$value` and `$type`
- `$type` must be `"color"` or `"dimension"` to be indexed
- Nesting depth is unlimited
- Group nodes may carry a `$type` that is inherited by children
